
# Module B Architecture

## 1. Overview

Module B is responsible for processing and optimizing synthetic security logs before they are stored in OpenSearch.

## 2. Processing Flow

1. Synthetic logs are generated by Module A.
2. Vector receives logs from the configured sources.
3. Incoming logs are parsed and normalized.
4. Sensitive information is masked.
5. Required detection fields are preserved.
6. Approved unnecessary fields are filtered.
7. Processed logs are forwarded to OpenSearch.
8. Module C uses the processed logs for detection.

## 3. Components

| Component | Responsibility |
|---|---|
| Module A | Synthetic log generation |
| Vector | Log collection and processing |
| Module B | Processing rules and validation |
| OpenSearch | Processed log storage and search |
| Module C | Security detection scenarios |
